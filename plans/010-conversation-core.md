# 010 对话与教学内核

- 状态：DONE
- 优先级：P0
- 范围：课程问答、单题问 AI、共享对话上下文、学习者记忆
- 依赖：009 学习闭环基线

## 1. 目标

把对话能力从两个页面中的独立提示词提升为课程级核心能力：

- 单题问 AI 能在刷新、退出和重新进入后恢复，并根据用户当前一句话切换教学方式。
- 课程问答能理解追问指代，在第一次检索不足时进行一次可解释的补救检索。
- 两个入口共用服务端消息、上下文预算、来源有效性和可观测性基础，但保留不同策略。
- 学习者掌握度继续使用结构化事实；偏好和已确认误解使用可查看、可纠正的记忆。

不以“传更多历史消息”作为完成标准。当前消息、题目状态、来源状态和学习状态必须是独立的结构化输入。

## 2. 外部实现取舍

| 项目 | 采用 | 调整 | 不采用 |
|---|---|---|---|
| OpenTutor | 学习者画像、教学策略、理解检查 | 中文意图与当前题目状态由本项目实现 | 整套多 Agent 编排、绝对禁止直接回答 |
| RAGFlow | 追问独立改写、充分性检查、补救查询 | 最多补救一次，继续使用现有授权与引用校验 | 无上限递归检索 |
| Tutor-GPT | 当前消息单独标记、旧消息摘要 | 只借鉴设计，不复制 GPL 代码 | 外部 Honcho、保存内部思维过程 |
| AnythingLLM | 短期上下文与长期记忆分离、记忆可管理 | 记忆限定在课程和用户作用域 | 自动保存模型推测出的用户事实 |
| Dify | 按预算保留完整回合 | 使用本项目的确定性 token 估算 | 固定最近 N 条作为唯一裁剪规则 |

## 3. 固定边界

- 不保存或展示模型 chain-of-thought、隐藏推理或 Provider 原始响应。
- 单题作答前继续保护最终答案；概念解释、类比例子和解题方法不应被一并禁止。
- 作答后允许完整解析、答案比较、错误定位和迁移练习。
- 课程问答继续只使用当前有效且经过授权的课程资料，保留 CitationValidator 和来源变化检查。
- 历史回答的来源失效后，不再作为可靠回答上下文。
- 不引入外部记忆服务、向量数据库或新的模型供应商。
- 不在本计划中重做 PDF 解析、学习单元投影、题目生成或掌握度算法。

## 4. 目标结构

共享层负责：

1. `Conversation`：课程、用户、场景和可选题目作用域。
2. `ConversationMessage`：角色、正文、当前意图、教学模式、来源、顺序和时间。
3. 上下文装配：当前消息独立传入；最近完整回合按 token 预算选取；旧内容后续压缩为摘要。
4. 来源有效性：只有仍有效的来源型历史回答可以进入可靠上下文。
5. 可观测性：记录意图、上下文规模、检索轮次、拒答原因和 Provider 元数据，不记录私有正文。

策略层分为：

- `course_qa`：追问改写、多查询检索、证据充分性、引用回答。
- `practice_tutor`：题目状态、用户尝试、当前意图、教学策略、答案保护。

## 5. 阶段与执行步骤

### 阶段 A：共享持久化与单题会话恢复（已完成）

要做什么：

- 扩展现有 `conversations`，区分 `course_qa` 和 `practice_tutor`。
- 对单题会话记录 `practice_session_id` 与 `practice_question_id`，同一用户、练习场次和题目只有一个会话。
- 新增通用 `conversation_messages`，持久化用户和助手消息、意图、模式、引用和顺序。
- 新增单题会话读取 API；发送 API 不再信任前端传入的历史，而由服务端装配历史。
- 前端打开问 AI 时读取服务端记录，发送成功后使用服务端消息更新页面。

怎么做：

- 新增 Alembic migration，旧 `conversations` 回填为 `course_qa`。
- 保留现有课程问答表和 API，避免一次性迁移 `query_runs`。
- 历史选择按完整 user/assistant 回合和估算 token 预算裁剪，当前消息不重复放入 history。
- 模型成功后在一个事务中保存本轮 user/assistant 两条消息；模型失败不写入半轮对话。
- GET 和 POST 都重新校验用户、课程、练习会话、题目及来源状态。

收口条件：

- 对话在刷新、退出和重新进入后完整恢复。
- 前端请求不再携带可伪造的 `history`。
- 跨用户、跨课程或不属于练习会话的题目不能读取对话。
- 同一道题重复打开不会创建多个会话。
- 迁移、Python 契约、OpenAPI、TypeScript schema 与 API 集成测试通过。

### 阶段 B：当前意图优先与自适应教学（已完成）

要做什么：

- 将单题当前意图分为：`hint`、`clarify`、`example`、`answer_check`、`solution`、`reflection`、`source`。
- 明确当前消息优先级高于历史答案和上一轮教学策略。
- 根据是否已提交答案，选择不同的答案保护规则。
- 维护提示层级和已知尝试状态，为后续误解记忆提供结构化事实。

怎么做：

- 先使用可测试的中文确定性路由识别明确意图；未命中时使用 `hint` 或上下文默认值。
- 将 `current_intent`、`current_message`、`attempt_state`、`conversation_history` 分开写入 Provider payload。
- `example` 生成同概念的平行例子；`clarify` 换一种表达；`answer_check` 检查推理但作答前不确认最终选项；`solution` 作答前只给方法或类比题，作答后给完整解法。
- 保留答案泄露检测，并针对不同意图调整允许的信息，而不是统一禁止解释。

收口条件：

- `123 -> 你能给个例子吗` 返回例子，不再继续点评 `123`。
- “我没懂，换个说法”会重新解释，不机械重复上一条提示。
- 作答前不能泄露正确选项或最终计算结果；作答后能完整比较答案。
- 意图、模式和消息一起持久化并在恢复后保持一致。
- Provider 提示词、泄露重试和意图路由单元测试通过。

### 阶段 C：课程问答追问理解与检索补救（已完成）

要做什么：

- 识别新问题、追问、比较、总结和澄清。
- 将含指代或省略的追问改写为独立问题。
- 第一次证据不足时，生成 1-3 个互补查询并最多补救一次。
- 区分索引不可用、零候选、低于阈值、来源变化、引用失败和模型主动拒答。

怎么做：

- 新增有严格 JSON 契约的 query planner；Provider 不可用或输出无效时回退到确定性当前实现。
- 先检索独立问题；仅在证据门判定不足时执行补救查询，控制时延和费用。
- 对多次结果按 chunk 去重并做稳定排名融合，仍由现有授权逻辑过滤。
- 保存检索轮次和最终拒答诊断；UI 显示可操作原因，不暴露内部阈值。
- 回答模型继续接收原始当前问题、独立问题和有效历史回答，引用只能来自最终授权候选。

收口条件：

- `什么是进程？ -> 它和线程有什么区别？` 能正确补全指代。
- 第一次检索不足、补救查询命中时能够回答且引用正确。
- 补救后仍不足时明确说明缺少哪类资料，不再统一显示同一句话。
- 每轮最多一次补救，不会形成递归 Agent 循环。
- 删除来源后，旧回答不参与可靠上下文，既有来源变化测试继续通过。

### 阶段 D：摘要、学习者记忆与可观测性（已完成）

要做什么：

- 为长会话增加滚动摘要，不无限增长历史。
- 新增课程级 `LearnerMemory`：明确偏好、已确认误解、学习目标和置信度。
- 将掌握度、作答记录和记忆分开；掌握度仍是确定性结构化数据。
- 提供记忆查看、修改和删除能力。

怎么做：

- 最近完整回合保留原文，超出预算的已完成回合进入有版本号的摘要。
- 只从用户明确表达或已确认的错误模式中提取候选记忆；助手推测不能直接落库。
- 记忆包含作用域、类型、内容、置信度、来源消息和最后确认时间。
- 上下文按当前课程和相关概念检索少量记忆，不把全部记忆塞入提示词。
- 增加脱敏指标：意图分布、恢复成功率、补救检索成功率、拒答分类和 P95 延迟。

收口条件：

- 长会话上下文始终处于预算内，且不截断单个问答回合。
- 用户能看见并纠正系统记住的偏好或误解。
- 未经确认的模型推断不会成为长期记忆。
- 删除课程或用户后相关会话、消息、摘要和记忆级联删除。
- 日志和指标不包含完整课程正文、答案或用户私密消息。

## 6. 回归与验收矩阵

| 场景 | 预期 |
|---|---|
| 单题输入 `123` 后要求例子 | 当前意图为 `example`，不重复点评旧输入 |
| 单题作答前直接索要答案 | 给方法或类比，不暴露正确选项/最终数值 |
| 单题提交后要求完整过程 | 返回完整解析并对比已提交答案 |
| 刷新后重新打开问 AI | 服务端历史恢复，顺序和引用一致 |
| 课程问答追问“它呢” | 改写成含明确主体的独立问题 |
| 首次检索低分，第二查询命中 | 使用融合后的授权证据回答 |
| 两轮检索都不足 | 返回具体诊断和建议补充的资料类型 |
| 历史来源被删除 | 旧回答不进入可靠上下文，也不展示可用引用 |
| Provider 超时或坏响应 | 不保存半轮助手消息，用户可重试 |
| 并发或重复请求 | 不产生重复顺序或跨会话串话 |

本计划只有在以下条件全部满足后才能标记 DONE：

- 阶段 A-D 的收口条件全部满足。

- 使用真实页面验证桌面和移动视口，不出现消息、来源和输入框重叠。
- 计划文档、对话行为文档和 API 契约与实现一致。
- 不把 `output/`、私有课程材料、Provider 凭据或模型内部推理提交到 Git。
