# 学习闭环 V1

## 用户路径

1. 用户进入一个资料已经审核、存在活动 Revision 和可用 chunk 的课程。
2. 系统将原始章节树投影为章节范围和知识目标；用户自行选择 1-10 个可练习范围，并请求 1-10 道题。题目数不得少于范围数，以保证每个所选范围至少分到一道题。
3. 真实 Chat Provider 从本次课程范围的 Evidence 片段生成结构化选择题或判断题。题干、答案、解释和 Evidence 引用在服务层校验后才会持久化。
4. 用户从仍然有效的题目创建练习会话，逐题提交答案。服务端记录一次幂等 attempt，返回正确性、解释和来源入口。
5. 每次作答按纯函数规则更新该用户/课程/学习单元的掌握等级和下一次复习时间；会话完成后显示正确率、薄弱单元和下一步复习动作。

## V1 固定边界

- 题型只有 `single_choice` 和 `true_false`；不实现主观题、作文、语音或开放题评分。
- 单次练习支持 1-10 道题和 1-10 个互不重叠的范围；题目数不得少于范围数。章节范围会在章内抽样，知识目标适合精准练习；不支持全课程生成和后台无限预生成。
- 学习单元是课程级稳定实体，`canonical_key` 在课程内唯一，`kind` 只有 `section` 和 `concept`。学习单元 ID 不使用图谱节点 ID。原始子章节仍保留用于来源和证据追踪，但练习 API 不把它们作为独立入口。
- 每个可练习学习单元必须至少绑定一个当前活动 Revision 的来源。来源绑定记录 `document_id`、`revision_id`、`chunk_id`、`content_sha256` 和既有 locator vocabulary。
- 顶层主题会聚合自身及子章节的当前有效 Chunk，并按 Chunk 去重；单个有效片段至少达到正文阈值，或多个片段达到组合阈值，才标记为 `practice_status=ready`。
- 课程资料更新或用户认为主题投影异常时，可以点击“重新整理学习单元”；该操作显式重建当前确定性投影，保留题目、来源和掌握度历史，不会自动重新调用大模型生成题目。
- 对文件名形如 `《操作系统》第3章 处理机调度与死锁.pdf` 的扁平资料，文档章节会作为顶层主题，原始小标题只参与证据聚合，不作为新的练习入口；当前旧投影会保留历史引用，但标记为不可用于新练习。
- 题目生成未配置真实 Provider、没有活动索引、资料未审核或 Evidence 不足时明确失败；不使用运行时假模型。已有且来源仍有效的题目仍可作答。
- 当前图谱算法、图谱画布、解析器、云队列和权限模型不在本计划内。

## 题目有效性和拒绝规则

题目只有在所属用户和课程匹配、来源 document 未删除、来源 revision 仍为该 document 的活动 Revision、资料审核状态为 `approved`、chunk 仍存在且内容哈希匹配、引用 locator 属于该 chunk 时才有效。资料删除、活动 Revision 切换、chunk 删除或哈希变化后，题目标记为 stale 或在查询层过滤，不能开始新的练习。

Provider 原文不持久化。未经结构校验的 Provider 输出、无 Evidence 的解释、答案越界、重复选项、多答案或跨课程引用一律拒绝。

学习单元在 UI 显示“可练习”前和批次创建时必须通过同一套证据充分性预检；资料不足时显示不可练习原因，不把失败推迟到模型调用阶段。当前只做确定性顶层投影，不把跨文档语义聚类或大模型主题命名当作已完成能力。

## 掌握度和复习规则

掌握等级为 0-3：`new`、`learning`、`review`、`mastered`。首次正确升一级，错误降一级并钳制在 0；连续正确继续推进。查看提示后答对最多升一级，提示、错误和完成复测分别记录在 attempt 事实中。复习间隔按等级使用 0、1、3、7 天；错误或低掌握度回到当天/次日。所有时间由服务端 UTC Clock 计算。

## 脱敏验收数据

验收 fixture 只使用公开、合成的短文本，不包含私有课程资料或 Provider 凭据：

- 章节 `函数基础`：概念 `函数定义`、`定义域`，各绑定一个活动 Revision chunk。
- 章节 `矩阵基础`：概念 `矩阵加法`，绑定一个活动 Revision chunk。
- 六道题分别覆盖三个单元，每个单元两题，题型混合选择题和判断题；题目解释只引用上述 chunk。

这些数据用于契约、API 集成和 Playwright mock 验收，不代表真实模型质量，也不作为题库预生成数据。

## 不做事项

不重做图谱关系算法，不修改问答拒答、CitationValidator、资料删除或 Revision 激活语义，不新增外部队列，不保存 Provider credential、原始响应、对象路径或私有正文快照。

## 操作员验证

- `no-provider`：未设置聊天凭据时确认新批次返回可操作的 Provider 不可用错误，已有有效题目仍能练习。
- `test-double`：仅在测试注入边界使用确定性 Provider 响应；测试结果不称为真实模型质量。
- `live-provider`：仅在显式配置真实 Chat Provider 时运行，验证结构化输出仍经过 Evidence 和来源校验；不得将凭据写入日志或数据库。
- `regenerate-learning-units`：在学习页点击“重新整理学习单元”，确认章节型资料被整理为文档顶层主题、不可练习的旧投影不再出现在新练习入口；随后选择新主题，再点击“生成题目”。
- 复核迁移、OpenAPI、Python 契约、Web 生成 schema、unit/integration/E2E 命令和最终 `git diff --check`。
